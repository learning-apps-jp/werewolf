# タブレット1台で遊ぶ人狼アプリ 仕様書

作成日：2026-10-01 ／ バージョン：1.6（タイマー終了音・GitHub Pages公開を反映）

## 1. 目的と対象

同じ場所に集まった参加者が、タブレット1台を順番に回して通常の人狼を遊べるアプリ。アプリが配役・夜の能力処理・投票・勝敗判定を担当し、専任のゲームマスター（GM）なしでも全員が参加できる。会話は対面で行う。

- 対象人数：5〜20人。初めての場合は6〜10人を推奨。
- 想定時間：20〜60分。人数・議論時間・役職で変動する。
- 対応：iPad／Androidタブレットのブラウザ。横向きを優先し、縦向きにも対応。
- 日本語、タッチ操作、アカウント不要。読み込み後はオフラインで遊べるPWAを想定。
- 初版は昼と夜を繰り返す通常人狼。ワンナイト人狼は別ゲームとして扱い、役職や勝利条件を混ぜない。
- この依頼の成果物は仕様書。実装・公開は次の工程。

## 2. ルール確認と採用方針

人狼は配役を秘密にして話し合い、昼の追放と夜の能力行使を繰り返すゲーム。運営団体や商品によって細部が異なるため、本アプリでは以下を「アプリ標準ルール」として採用する。特殊役職の細部はアプリ独自の選択であり、普遍的な公式ルールとは扱わない。

確認した一次情報：

- [人狼 ザ・ライブプレイングシアター：人狼とは](https://oracleknights.co.jp/jinrou-tlpt/000/rule.php) — 基本の昼夜進行、陣営、役職、勝敗。公演独自の初期情報もある。
- [人狼村池袋本店：ルール・役職説明](https://hermit-stp.co.jp/rule/) — 基本役職に加え、共有者・猫又・妖狐・背徳者などの説明。店舗独自役職もある。
- [ワンナイト人狼 公式ストア](https://1nite_jinro.stores.jp/about/) — 短時間の別形式として確認。

### 2.1 標準の進行

1. 参加者と配役、ルールを設定し、全員で公開ルールを確認する。
2. ランダムに配役。各自が自分の役職・勝利条件・知ってよい仲間だけを確認する。
3. 初夜：仲間情報の確認、占いなどの初期行動。襲撃・護衛は行わず、初夜の脱落者は出さない。
4. 昼：生存者が議論する。役職の申告、嘘、推理は自由。ただし秘密画面を他人に見せない。
5. 投票：生存者が1人1票を秘密投票し、最多得票者1人を追放する。
6. 追放を確定し、勝敗を判定する。
7. 夜：生存者全員が端末を回し、能力を入力する。全入力後にまとめて処理する。
8. 朝：脱落した人の名前だけを発表し、勝敗判定後、続く場合は昼へ戻る。

脱落者は議論・投票・夜行動に参加しない。勝敗は陣営単位であり、脱落者も所属陣営が勝てば勝利する。追加役職にも同じ勝利条件を適用する。

### 2.2 基本の勝敗

生存者について、人狼カウントをW、村人カウントをHとする。所属陣営と人数カウントは別項目とする。

- W = 0：村人陣営の勝利条件が成立。
- W > 0 かつ W ≥ H：人狼陣営の勝利条件が成立。
- 狂人・狂信者は人狼陣営だがHに数える。
- 陣営は村人・人狼の2つだけ。第三陣営や個人勝利は設けない。
- 勝敗判定は追放の確定後と、夜の一括処理の完了後に行う。

### 2.3 投票の標準

- 自分への投票と棄権は禁止。全員の入力完了前に票数・投票先を見せない。
- 同率最多なら、その候補だけを対象に再投票する。候補者も投票し、自己投票は禁止。
- 再投票でも同票なら、その日は追放なし。自動抽選は標準では使わない。
- 確定前は選び直せる。確定後は次の参加者へ渡す遮蔽画面に移る。
- 公開するのは候補ごとの得票数。誰が誰に投票したかは標準では非公開。

## 3. タブレット1台での秘密操作

### 3.1 共通の受け渡し

「○○さんに渡してください」→「本人が長押しして開く」→秘密画面→選択と確認→「隠して次へ」の順にする。長押しは誤操作防止であり本人認証ではない。任意で各参加者のPINを設定できる。PINは他人に見られない状態で本人が登録する。

- 秘密情報は受け渡し画面・共通画面・音声・通知に出さない。
- 端末を机に置き、次の人が受け取るまでは画面を伏せる運用を案内する。
- 配役確認、夜行動、結果確認は役職別に呼ばず、生存者全員を登録順に呼ぶ。
- 能力がない人にも同じ外観の「今夜の確認」画面を用意する。
- 1人の夜手番は設定された共通の最低表示時間（標準10秒）を確保する。操作が長引く場合は延長できる。
- 時間の差による推測や物理的な覗き見を完全には防げないため、操作中は見ない・話しかけないという参加者ルールを開始前に表示する。
- 秘密画面の無操作30秒、タブ切替、画面ロック、再読み込みでは情報を隠す。復帰後は本人確認画面から再開。
- ブラウザの戻る操作で前の参加者の情報を再表示しない。
- 役職名や操作内容の音声読み上げは行わない。公開の進行案内のみ任意で読み上げる。

### 3.2 人狼の襲撃先

単一端末では秘密の同時相談が難しいため、標準は人狼による秘密投票方式とする。これは本アプリの進行上の変更点であり、開始前に説明する。

- 各人狼が自分の手番で、生存している人狼以外の1人を選ぶ。
- 人狼には、ほかの生存人狼の入力済みの襲撃先と未入力状態を表示する。全人狼の最多票の対象を襲撃する。夜の追加周回はなく、最後の人狼がまだ入力していない時点では全入力・確定した襲撃先を表示できない。襲撃の成否は朝まで知らせない。狂人・狂信者には入力を共有しない。
- 同票は該当候補からアプリが無作為抽選する。抽選結果は終了後の履歴に残す。
- 公開画面では投票の一致・不一致、襲撃先を明かさない。入力時点では後の順番ほど仲間の入力を多く見られることを開始前に説明する。
- 人狼同士のチャット・伝言機能は初版の対象外。

### 3.3 夜は1周で行動と確認を完了

夜開始時の生存者全員に、登録順で1回ずつ端末を回す。占い師は対象を選んで確定すると、その場で人狼かどうかを確認する。霊媒師は自分の画面で直前の追放者の判定を確認する。その他は行動の確定または共通確認を済ませて次へ渡す。結果確認だけの2周目は設けない。

占い結果は確定時に保存し、隠す・中断・再読み込みで占い直しにならない。全員の手番後に襲撃と護衛を解決して朝へ進む。その夜に襲撃される能力者も、朝の脱落発表前に結果を受け取る。全入力前には襲撃の成功や脱落予定を知らせない。

## 4. 役職カタログ

下表は本アプリの採用仕様。占い・霊能の標準結果は「人狼／人狼ではない」の2種類とする。役職の正式な正体までは分からない。

### 4.1 基本役職（5種類）

| 役職 | 陣営／カウント | 能力・秘密情報 | 占い／霊能 |
|---|---|---|---|
| 村人 | 村人／H | 能力なし。議論と投票に参加 | 非人狼／非人狼 |
| 人狼 | 人狼／W | 仲間の人狼を知る。毎夜の襲撃投票 | 人狼／人狼 |
| 占い師 | 村人／H | 毎夜、自分以外の生存者1人を調査 | 非人狼／非人狼 |
| 霊媒師 | 村人／H | 夜、直前の昼に投票で追放された本人の判定を受け取る | 非人狼／非人狼 |
| 騎士 | 村人／H | 毎夜、自分以外の1人を襲撃から守る。連続護衛可。成功したかは知らせない | 非人狼／非人狼 |

占いは初夜から本人が自分以外の生存者1人を選ぶ方式を標準とする。

### 4.2 特殊役職（好みで追加する3種類）

追加役職は「知っている情報が少し増える」ものに絞る。昼夜の進行、占い・霊能の判定、脱落と勝利条件は基本役職と共通。新しい夜操作は増やさない。

| 役職 | 陣営／カウント | 採用する能力・条件 | 占い／霊能 |
|---|---|---|---|
| 狂人 | 人狼／H | 能力なし。人狼の正体を知らず、人狼にも知られない | 非人狼／非人狼 |
| 共有者 | 村人／H | 必ず2人。開始時に互いの正体を知る | 非人狼／非人狼 |
| 狂信者 | 人狼／H | 全人狼を知る。人狼からは知られない | 非人狼／非人狼 |
共有者は「お互いに村人陣営だと分かる2人」、狂信者は「人狼の正体を知っている狂人」と説明する。基本配役は特殊役職なし。狂人・共有者・狂信者は好みで追加する。

妖狐・背徳者・猫又・白狼・恋人・道化師は今回の実装対象から除外する。第三陣営、道連れ、判定の例外、特殊な勝利条件、役職交換、感染、蘇生は採用しない。

## 5. カスタマイズ

### 5.1 配役とプリセット

- 各役職の人数を増減し、合計人数を常時表示。村人で残りを埋める操作を用意する。
- 基本／特殊の2分類で役職を表示する。各説明は短い一文とし、詳しい説明はタップして開く。
- 標準案：6人＝村人3・人狼1・占い師1・騎士1。8人＝村人3・人狼2・占い師1・騎士1・霊媒師1。10人＝村人5・人狼2・占い師1・霊媒師1・騎士1。
- 共有者は村人2人を置換する。狂人・狂信者は村人1人を置換する。すでに狂人を入れている場合は狂信者と置換し、両方を同時には入れないことを推奨する。
- おすすめ配役は「はじめて」「基本」「共有者を追加」「狂信者を追加」。「はじめて」は村人・人狼・占い師を中心に、「基本」は基本5役職だけで構成。追加役職は村人を置換し、狂人も人数ボタンから任意で追加する。
- 追加の目安は共有者が10人以上、狂信者が8人以上。少人数では片方の陣営に情報が偏りやすいため注意を表示する。
- 10人の追加例：共有者なら村人3・共有者2・人狼2・占い師1・霊媒師1・騎士1。狂信者なら村人4・狂信者1・人狼2・占い師1・霊媒師1・騎士1。
- プリセットはアプリの初期提案であり、バランス保証はしない。名前を付けて保存・複製・削除できる。
- 配役固定は参加GMなしモードでは不可。公平に無作為配役する。

### 5.2 変更できるルール

| 項目 | 標準値 | 変更候補 |
|---|---|---|
| 議論時間 | 5分 | 1〜15分、時間制限なし |
| 初夜の占い | 本人が対象を選ぶ | 占いなし |
| 騎士の自己護衛 | 不可 | 可 |
| 同じ相手への連続護衛 | 可 | 不可 |
| 昼の投票先公開 | 得票数だけ | 投票者と投票先も公開 |
| 昼の同票 | 再投票1回→追放なし | 再投票1回→候補から無作為追放 |
| 脱落時の役職公開 | 非公開 | 昼の追放者のみ公開、全脱落者を公開 |
| 夜の最低操作時間 | 10秒 | 5〜30秒 |
| 公開進行の音声 | オフ | オン |

試合途中の配役・能力・勝利条件変更は不可。議論タイマーの延長・一時停止は可能。保存するのはルールと配役人数であり、前の試合の秘密情報は含めない。

### 5.3 分かりやすいカスタマイズの範囲

カスタマイズの中心は役職の人数、追加役職のオン・オフ、議論時間、護衛と投票の設定、ルールセットの保存とする。自由な能力の作成エディタは今回の実装対象から外す。

- 役職名は騎士・霊媒師に統一する。
- おすすめの設定を初期表示し、細かな設定は「詳細設定」にまとめる。
- 設定を変えた場合は開始前の確認画面に変更点を短く表示する。
- 保存したルールセットは名前を付けて複製・編集できる。
- JSONでの入出力は将来の必要性を見て検討し、初版では画面内の保存だけを提供する。

### 5.4 開始前の検証

開始を禁止する例：配役合計不一致、人狼カウント0、開始時点でW ≥ H、共有者が1人または3人以上、狂信者が2人以上、未対応の役職。共有者0人はオフとして有効。

注意を表示する例：10人未満で共有者、8人未満で狂信者、共有者と狂信者の併用、狂人と狂信者の併用。注意には原因と基本構成へ戻す操作を示す。人数目安はアプリの提案であり、バランスを保証するものではない。

## 6. 能力の解決と勝敗判定

### 6.1 夜の一括処理

夜開始時の生存者・役職・状態を固定して、全員の選択を収集する。端末の操作順を能力の実行順にしない。

1. 各自の手番で対象を検証し、占い・霊媒の結果を本人に即時表示して保存する。護衛は選択を保存する。
2. 人狼の襲撃投票を集計し、襲撃対象を決定する。
3. 襲撃対象が護衛されていれば脱落者なし。そうでなければ対象1人の脱落を確定する。初夜の襲撃はない。
4. 全員の手番完了後、そのまま朝に進む。結果確認の追加周回はない。
5. 全員集合の画面から、脱落者または「脱落者なし」を発表し、勝敗を判定する。

護衛の対象・成功したかどうかは個別にも公開にも通知しない。共有者と狂信者の初期情報は配役確認時に渡し、その後の夜処理を増やさない。

### 6.2 昼の処理

投票集計→追放1人または追放なしを確定→勝敗判定。霊能対象は投票で追放された本人だけ。

### 6.3 共通の勝利条件

W = 0なら村人陣営勝利。W > 0かつW ≥ Hなら人狼陣営勝利。それ以外は続行。共有者は村人陣営、狂信者は人狼陣営として同じ判定に従う。追加役職を選んでも勝利条件の説明は増えない。

## 7. 画面仕様

| 画面 | 主な内容・操作 |
|---|---|
| ホーム | 新しいゲーム、再開、遊び方、保存したルール |
| 参加者登録 | 名前・番号、順番変更、人数表示。空欄は参加者番号で補完、重複名は区別表示 |
| 配役設定 | 難易度とプリセット、人数増減、基本・特殊役職の説明、残り人数、検証 |
| 詳細ルール | 護衛・投票などの設定、設定保存 |
| 最終確認 | 全員向け配役内訳、採用ルール、1台での注意。開始後は固定 |
| 受け渡し | 次の人の名前と番号、長押し／任意PIN。秘密は非表示 |
| 秘密確認 | 自分の役職、陣営、勝利条件、許可された仲間、本人だけの履歴 |
| 夜の入力 | 使える能力、対象選択、確認。能力のない人にも共通確認 |
| 結果確認 | 夜の本人の手番内で調査結果を表示。追加周回はない。秘密画面内の役職紋章は用いるが、外に聞こえる役職別の音は使わない |
| 昼 | 日数、生存者、公開脱落履歴、議論タイマー、延長・一時停止 |
| 秘密投票 | 候補選択、確定、遮蔽。前の人の票は見せない |
| 朝・追放発表 | 名前と生存状態。設定で許された場合だけ役職公開 |
| 終了 | 勝者と成立理由、全員の役職、昼夜の履歴、同じ設定で再戦 |

秘密確認から一覧表示へ抜ける前に必ず遮蔽する。参加者モードに全役職一覧や秘密の管理画面を置かない。

## 8. 保存・中断・技術方針

- フロントエンド内のルールエンジンで処理し、試合中のサーバー通信を不要にする。
- 公開情報と秘密情報を別の表示モデルに分け、秘密情報をURL・ページタイトル・通知・アクセス解析・コンソールログへ出さない。
- 保存対象：設定、配役、日数、状態、確定済み行動、未完了の受け渡し位置、抽選結果。ブラウザ内に1試合だけ自動保存する。
- 夜の途中で再開しても、確定した入力を二重処理しない。確定前の選択は再入力、確定済みの選択は維持する。
- 抽選は暗号学的乱数を使い、一度決まった配役・襲撃先を再読み込みで引き直さない。
- タイマーは終了予定時刻で管理し、バックグラウンドでも表示時間がずれない。一時停止中は残り時間を保持する。
- 保存失敗は見える形で知らせる。進行中の保存を黙って上書きせず、新規開始時に既存試合の破棄を確認する。
- ゲーム終了後は再戦用設定を残し、秘密情報の保存は標準で削除する。履歴を残す場合は終了後に明示的に保存する。
- ブラウザ内保存とPINは端末を共有する際の補助。開発者ツールや端末所有者による解析への強い機密保証はしない。
- 既存ゲーム一覧に組み込む場合は別ディレクトリの通常人狼アプリとして追加し、既存ワンナイト人狼は別項目として維持する。
- 将来公開する場合の既定先は learning-apps-jp。公開URLは個人GitHub名を含めず、例として https://learning-apps-jp.github.io/werewolf/ を使用する。リポジトリ名・利用可能性は公開時に確認する。

### 8.1 主なデータ

| データ | 主な項目 |
|---|---|
| RuleSet | バージョン、難易度、配役人数、護衛・投票などのルール |
| RoleDefinition | ID、表示名、陣営、人数カウント、判定、能力、勝利テンプレート、依存条件 |
| Player | ID、名前、席順、役職ID、生存状態、秘密情報 |
| GameState | 試合ID、固定ルール、日数、フェーズ、操作対象、入力・結果の確認状況 |
| Action | 夜・投票ラウンド、行動者、能力、対象、確定状態 |
| Event | 連番、発生時点、脱落原因、抽選結果、公開範囲、勝敗理由 |

陣営・人数カウント・占い判定・霊能判定を単一の「役職分類」で代用しない。別名でも役職IDを維持する。試合開始時点の定義を保存し、アプリ更新が進行中の試合に影響しないようにする。

## 9. 操作性

- タップ領域は最低48px。名前一覧は人数が増えても押し間違えにくくする。
- 色だけで陣営・生存状態を表現せず、文字とアイコンを併記する。
- 高コントラスト、文字サイズ変更、動きを減らす設定に対応する。
- プレイ中は画面を暗くしすぎず、昼と秘密画面を明確に区別する。
- 初心者向け説明は「誰を選ぶか」「何が分かるか」「何をすれば勝つか」を短く表示する。
- 全画面・画面スリープ防止は対応ブラウザで提供する。使えない場合も通常表示で進行可能とする。

## 10. 実装段階と受け入れ条件

### 第1段階：基本版

基本5役職、全員への受け渡し、秘密投票、夜1周での行動と即時確認、標準ルールと詳細設定、配役案、勝敗判定、自動保存・再開、終了後の公開履歴。

### 第2段階：分かりやすい追加役職と保存

共有者・狂信者、難易度別のおすすめ、配役・ルールの保存、組み合わせ検証。第三陣営・連鎖脱落・自由な能力エディタの実装段階は設けない。

### 受け入れ条件

1. 8人の基本構成で、GMなし・端末1台で配役から勝敗表示まで完了できる。
2. 村人も人狼も同じ順で夜入力・結果確認を行い、共通画面に役職や未公開情報が出ない。
3. 人狼の襲撃投票が割れた場合も、仕様どおり1対象に決まり、再読み込みで変わらない。
4. 投票同票・再同票・護衛成功・人狼全滅・W = Hが仕様どおりに処理される。
5. 狂人をWに数えず、人狼だけが全滅した場合に村人陣営が勝つ。
6. 共有者は相方だけ、狂信者は人狼だけを初期情報として知り、他の参加者に情報が漏れない。人狼には狂信者を知らせない。
7. 追加役職を選んでも新しい夜行動・判定の例外・勝利条件が増えず、共有者と狂信者の占い・霊能結果は非人狼になる。
8. 配役確認・投票途中・夜入力途中・夜解決直後の中断から再開して、二重集計や秘密の即時表示が起きない。
9. iPad相当の横向き・縦向きとAndroidタブレットで、全参加者と操作ボタンが利用できる。
10. 追加役職の人数・難易度・ルールを保存し、同じ構成で再戦できる。
11. 不正な配役・壊れた保存データ・未対応バージョンは、説明付きで拒否または安全な復旧案を提示する。

## 11. 次工程で確認する事項

本仕様は通常人狼・専任GMなし・難易度を上げすぎない構成を既定として作成した。実装着手時に、主な参加人数とゲーム一覧への組み込み方を確認する。未指定なら第1段階を先に実装し、第2段階で共有者・狂信者の任意追加に対応する。

## 12. 作成したローカル版の範囲

werewolf/play.html に基本5役職と特殊3役職、8人の指定配役、初日からの自由占い、夜1周の進行、人狼間の入力共有、秘密投票、タイマー、保存と再開を実装済み。月夜の村のSVGイラスト、役職紋章、結果カード、背景の風景を追加。外部画像・フォントの読み込みなしでローカルファイルをオフライン表示できる。PIN、夜の最低操作時間、音声読み上げ、PWAインストール、スリープ防止は今後の拡張項目。公開先は https://learning-apps-jp.github.io/werewolf/ 。

## 13. GMなしでの発表と進行補助

### 結果の演出

- 全員集合の画面から「朝のお知らせを開く」「投票結果を開く」を押す。全員の準備が整うまでは結果を表示しない。
- 朝は夜明けの光、投票は封を開く表現を用い、約2.6秒の語りのあとで結果カードを表示する。
- 演出中は脱落者名・追放者名・得票数・次の進行ボタンを表示しない。処理済みの結果を演出するだけで、抽選や集計をやり直さない。
- 「すぐに結果を見る」でスキップ可能。動きを減らす設定ではアニメーションを無効にし、約1.2秒の静止した文言表示にする。
- 初日、朝の脱落、朝の脱落なし、投票追放、同票再投票、再同票で追放なし、抽選追放で語りを分ける。
- 「脱落者なし」は結果のみを伝え、騎士の護衛成功や護衛先を示唆する固有演出はしない。非公開役職や非公開投票先は発表文にも含めない。
- 発表後は脱落者の参加ルールと、話し合い・夜・再投票・勝敗確認のどれに進むかを明記する。発表文を再表示できる。

### 検討して追加した補助

| GMなしで起こりやすい問題 | 対応 |
|---|---|
| 全員が見ていないうちに結果が出る | 集合と準備の確認をしてから発表 |
| 間違えて話し合いを終える | 投票開始前の確認ダイアログ。閉じれば話し合いを続行 |
| タイマーが終わっても気づかない | 残り30秒と終了時の文言、終了時の色変更。自動進行はしない |
| 脱落後に発言や夜行動へ参加してしまう | 発表時に参加終了を案内し、生存者だけを操作対象にする |
| 同票時に誰が投票するか迷う | 生存者全員で再投票、候補者も自分以外へ投票と説明 |
| 現在のフェーズやルールが分からない | 公開画面の進行表示、話し合い画面からのルール確認 |

音声読み上げ、スリープ防止は必要性を見て追加する候補。現版では文字と視覚の案内に加え、公開発表だけに効果音を提供する。途中離脱者の自動退場は陣営バランスと勝敗を変えるため追加せず、現在の一時停止・保存再開を使う。

### 発表の受け入れ条件

結果が発表前の画面に漏れないこと、スキップ後に同じ発表が二重進行しないこと、各同票・朝の結果で適切な案内になること、非公開役職・護衛先が出ないこと、動きを減らす設定とタブレット／モバイル表示で操作できることを検証する。

## 14. 公開発表だけの効果音と通しプレー

- 朝の開始：柔らかいチャイム。投票発表の開始：低い打音。結果表示：短いベル。勝利発表：ファンファーレ。
- いずれも全員で見る公開画面でのみ再生する。役職確認・夜行動・調査結果・秘密投票・個人の受け渡しは常に無音。
- 非公開情報を知らせる音はない。朝と投票の発表前の音は、結果や役職によって変えない。
- 個人の画面へ進む時・中断時・タブが非表示になる時は、再生中／予約中の音も止める。音声の開始が遅れても、画面の公開状態を再確認してから鳴らす。
- 効果音は標準オン、控えめな音量。公開画面でオン／オフと音量を変更でき、ブラウザに保存する。ミュート切替自体に確認音は付けない。
- Web Audioによる生成で外部ファイル・外部通信は不要。非対応／再生制限時もゲーム進行を止めない。

6人の基本配役、8人の基本配役、10人の共有者入りをブラウザで自動操作し、勝敗まで通し検証した。テスト用の操作方針による確認であり、人間同士での戦術や配役バランスの評価ではない。全個人手番で音が生成されず、発表と勝利時にだけ生成されることを確認した。

改善として、対象を選んだ際に名前と席番号を確認表示し、同名の参加者は席番号付きの名前にして公開結果でも区別する。確定後の占い直し禁止、投票開始確認、保存再開、同票の案内、勝敗後の再戦も通しプレーで確認する。

## 15. 議論タイマーの終了音

タイマー終了音は全員が見る昼の話し合い画面でのみ鳴る。同じ終了時点では1回だけ通知し、毎秒のタイマー更新・画面再描画・保存再開で繰り返さない。一時停止中、時間制限なし、ミュートでは鳴らさない。延長すれば通知済み状態を解除し、新しい時間の終了時に1回通知する。期限が過ぎてからの延長は、現在時刻から丸1分を追加する。

音の準備は話し合い開始ボタンの操作時に行うが、その準備自体では音を出さない。個人の手番に切り替わると、終了音の余韻と予約中の音も停止する。設定は公開発表音と共通のオン／オフ・音量を使用する。
